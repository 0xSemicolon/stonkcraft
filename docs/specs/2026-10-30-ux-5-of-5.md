# UX to 5/5 on every cell of the matrix

Status: phases 0–4 implemented; phase 5 re-scored twice (4.80/5), scale-3 re-check pending (see Progress) · Date: 2026-10-30, updated 2026-10-31

## Why

The UX review of 2026-10-29 scored 18 surfaces (17 screens plus the blocks in the world) on 9 criteria. The
overall average is about 3.4/5. The terminal and the in-world blocks are close to done. The block screens and
the redstone-bot journey hold the score down.

| Column | Avg | What holds it down |
|---|---|---|
| Lay (layout holds up) | **3.2** | Wrapped text drawn at fixed y positions; 5 confirmed overlaps, plus text spilling past panel edges |
| Disc (findability) | **3.2** | Long lists behind cycle buttons; nothing explains where cards come from |
| Vis (visual polish) | 3.4 | Block screens use vanilla grey buttons inside teal panels; big empty areas |
| Safe (error prevention) | 3.5 | Esc discards edits silently; 10x default leverage; self-copy allowed |
| Eff (clicks and keyboard) | 3.6 | Enter doesn't save; cycling through 30 sensor modes |
| Fun | 3.6 | Static screens; nothing marks a bot's first trade |
| Copy (wording) | 3.7 | Live-trading leftovers; "0 = off" explained in one place only |
| Clar (clarity) | 3.8 | Unlabelled boxes (Access); Executor and Copy Desk density |
| Fbk (feedback and preview) | 4.0 | No Executor test fire; no Copy Desk preview; Kill Switch gives no feedback |

A cell can't reach 5 by tuning one screen at a time: most gaps come from three shared pieces. Those are
`BlockConfigScreen` (vanilla `Button` for Save/Cancel, and a `wrapped()` that doesn't return its height), the
absence of shared widgets outside the terminal's `Ui.chip`, and the absence of a check that catches regressions.
So the strategy is **measure → platform → sweep → journeys → re-score**.

## What a 5 means

Every column gets a written bar. Where possible the bar is checked by a machine, so a 5 is a fact, not an opinion.

| Column | 5/5 means | How it's checked |
|---|---|---|
| Lay | No text overlaps other text or widgets, and nothing leaves its panel. Holds at GUI scale 2, 3 and 4, and at 854×480. Long values ellipsize, with the full value in a tooltip. | **Automatic.** Layout lint in the tour (Phase 0) must report zero issues. |
| Vis | Every screen uses the HC widget kit; no vanilla grey widgets. Header, accent bar, account chip and footer are the same everywhere. No empty band taller than 40 px without an empty-state message. | Lint flags vanilla widgets; reviewer checks against screenshots |
| Clar | In one glance the screen answers three questions. What is this block? What is it doing right now? What will Save change? A status line on every block screen answers the middle one. | Reviewer, plus a "status line present" lint |
| Fbk | Every control shows its effect before it's committed (live preview, dry run or test fire). Every action confirms in place: a toast or status-line change, never only chat. | Reviewer checklist per control |
| Disc | No cycle button with more than 4 options (use dropdown grids). Every control has a tooltip. Every block screen shows what it needs next ("needs a card", "wire a redstone input"). | Lint counts cycle options and controls without tooltips |
| Safe | Esc with unsaved edits asks first, in the panel. Invalid input is flagged inline before Save. Destructive actions need shift-click or a second click. Defaults are safe: 2x leverage, self-copy refused. | Reviewer checklist, plus tour steps that try each mistake |
| Eff | Enter saves, Esc cancels, Tab moves through fields in visual order. Numbers take presets or scroll-wheel nudges. Core journeys meet click budgets (see Journeys). | Tour journey scripts count clicks |
| Copy | Meets a short style guide: units on every number, "0 = off" spelled out next to each such field, one name per market (AAPL, not xyz:AAPL), and no live-trading leftovers. | grep lint for banned phrases; reviewer |
| Fun | Each screen has one live element tied to its block, plus sound on Save and on fire. A bot's first trade, first profit and first copy get celebrated (advancement, particles, label flash). | Reviewer |

## Phase 0: make the score repeatable (1–2 days)

1. **Commit `UiTour`** as it stands.
2. **Layout lint.** When `hypercraft.uitour` is on, `Ui.text*`, the new `Ui.wrap` and every HC widget record
   their drawn rectangles each frame. The tour then checks three things on every screen:
   - no two text rectangles intersect
   - no text intersects a widget it doesn't belong to
   - nothing extends past the panel

   It writes `run/screenshots/ui_lint.json` and draws the problem rectangles in red on a second screenshot
   (`ui_*_lint.png`). This one check covers the whole Lay column, and it would have caught bugs 1–5 and today's
   Trade Executor overflow.
3. **Scale passes.** Run the tour at GUI scale 2, 3 and 4 and at 854×480 (`-Puitour=scale3`, and so on).
4. **Journey scripts.** Script the six journeys below as tour steps that count clicks and keystrokes and record
   the time to finish. Write the results next to the lint output.
5. **Freeze the rubric.** This document's bars don't change mid-project, so a score can't rise because a bar
   moved.

## Phase 1: the HC widget kit (3–4 days)

New classes in `client/ui`, built on the existing palette and `Ui.chip` look:

| Widget | Replaces | Fixes |
|---|---|---|
| `HcButton`, `HcToggle` (chip-styled `AbstractButton`, keyboard focus ring, tooltip slot) | vanilla `Button` in every block screen | Vis on 14 panels |
| `HcDropdown` (grid popup, generalised from the Signal Mixer's `Op ▾` menu) | cycle buttons in Sensor (~30 modes), Account Display (~18 figures), Executor, Kill Switch | Disc, Eff |
| `HcField` (label above the box that stays visible while typing, unit suffix, inline error, scroll-wheel nudge, presets) | bare `EditBox` + placeholder hint | Clar and Safe on Access, Copy Desk, Executor |
| `Flow` layout: `row()`, `gap()`, `wrap(text) → height`, `footer()`; every element is placed below the last one's measured bottom | fixed `py + N` positions and `BlockConfigScreen.wrapped()` | Lay everywhere; the root cause of bugs 1–5 |
| `Footer` (Save/Cancel or Save/Apply, a dirty flag, Enter = Save, Esc = cancel with an "unsaved changes" confirm in the panel) | the Save/Cancel buttons in `BlockConfigScreen.init()` | Safe, Eff, consistency |
| `StatusLine` (one line under the header: "Linked to Tour · watching BTC ≥ 100,000 · OFF") | nothing | Clar, Disc |
| `Toast` (in-panel confirmation that fades) | chat messages | Fbk |

Then port `BlockConfigScreen` to the kit. Every block screen inherits from it, so this one move restyles 9
screens. Port `FundScreen`, `VaultScreen`, `VaultSetupScreen`, `AccessScreen`, `UnitBridgeScreen`,
`CopyDeskScreen` and `WelcomeScreen` one at a time after that.

## Phase 5: re-score

1. Run the tour at every scale. Lint must be zero and every journey must meet its budget.
2. Score with this rubric twice: once by the implementer, once by a reviewer with no context (a fresh agent or
   a playtester) given only the screenshots, the journeys and this rubric. A cell is 5 only if both say 5. Each
   5 cites the screenshot that shows it.
3. Every cell below 5 goes back into Phase 3 as a row. Repeat until none are left.

## Order and expected scores

| After | Expected overall | Why |
|---|---|---|
| Phase 0 | 3.4 | Measurement only |
| Phase 1 + 2 | ~4.2 | Lay → 5 across the board, Vis +1 on 14 panels, Safe and Eff +0.5 from `Footer` |
| Phase 3 | ~4.7 | Disc, Fbk and Clar lifted panel by panel |
| Phase 4 + re-score loops | 5.0 | Journey gaps and Fun close, then whatever the re-score finds |

Phases 0–2 come first because they have the most effect for the effort and stop regressions. Phase 3 can run
in parallel, one panel per change, once the kit exists.

## Risks

- **Fun and Vis are taste.** The second reviewer and the cited screenshot keep them honest. If the two
  reviewers disagree twice on a cell, a playtester decides.
- **Vanilla constraints.** Minecraft's `EditBox` and focus handling limit what `HcField` can do. Wrap them; don't
  fork them.
- **Scope creep.** Only rows in this document count. New ideas go into a follow-up spec.
- **Layout lint false positives** (for example, intended overlays like the coin suggestion list). Mark overlays
  explicitly; anything not marked is an error.

## Out of scope

New blocks, new trading features, and anything outside the screens, HUD and blocks scored in the matrix.
